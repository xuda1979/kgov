1 引言
============================================================

1.1 编写目的
    本手册面向 Kafka-Govern（kgov）V1.0 的使用者，说明软件的安装、
    配置、各功能模块的操作方法、参数含义以及常见故障处理方法，
    帮助使用者快速上手完成 Kafka 主题治理日常操作。

1.2 软件范围
    kgov 是一款企业级大数据治理辅助工具（自托管式 Kafka 主题治理
    平台），面向 Kafka + Schema Registry 环境，提供：
    - Schema 演进兼容性检测（schema-diff）；
    - 脏数据规则扫描与 CI 门禁（check）；
    - 治理报告生成与导出（report）；
    - Schema Registry 客户端（registry）；
    - 真实 Kafka 对接扩展（topics / broker 扩展）；
    - 通用导出接口（export）。
    本软件自托管、可离线运行，不依赖云服务与外部数据库。

1.3 术语定义
    - topic（主题）：Kafka 中消息的逻辑归类单元。
    - Schema（模式）：消息数据的结构定义，支持 Avro 与 JSON Schema。
    - 兼容性：Schema 演进前后能否互读，分为 Breaking（破坏性）、
      Non-Breaking（非破坏性）、Additive（新增兼容）三级。
    - Schema Registry：Confluent 生态的注册表服务，管理 Schema 版本。
    - DSL：规则声明语言，本软件用其描述字段约束。
    - 退出码：程序结束返回给操作系统/CI 的数字状态。

1.4 参考资料
    - 《Kafka-Govern 软件设计说明书》V1.0；

2 安装与卸载
============================================================

2.1 环境要求
    - 操作系统：Linux（Ubuntu 22.04 LTS / Debian 12 及以上）、
      macOS 12 及以上、Microsoft Windows 10/11（WSL2 或原生 Python）；
    - 运行时：Python 3.11 及以上；
    - 硬件：x86-64 / ARM64，CPU 主频不低于 2.0GHz，内存不低于
      2GB（开发环境推荐 4GB），硬盘剩余空间不低于 500MB；
    - 可选组件：连接真实 Kafka 集群需安装 confluent-kafka。

2.2 安装步骤
    1. 创建虚拟环境（推荐）：
           python3 -m venv .venv
           source .venv/bin/activate        # Windows 为 .venv\Scripts\activate
    2. 安装软件包：
           pip install -e .
       核心依赖自动安装：avro>=1.11、jsonschema>=4.18、PyYAML>=6.0。
    3. 安装开发/测试依赖（可选）：
           pip install -e ".[dev]"
    4. 安装真实 Broker 扩展（可选）：
           pip install -e ".[broker]"
    5. 验证安装：
           kgov --help
       显示可用子命令说明安装成功。

2.3 卸载步骤
    - 卸载软件包：pip uninstall kgov
    - 卸载全部依赖（可选）：pip uninstall -y kgov avro jsonschema
      pyyaml confluent-kafka
    - 删除虚拟环境：rm -rf .venv（Windows 为 del .venv）

3 操作说明
============================================================

3.1 总览
    命令行入口为 kgov，子命令包括：
        kgov schema-diff     Schema 演进兼容性检测
        kgov check           脏数据规则扫描（CI 门禁）
        kgov registry        Schema Registry 客户端
        kgov topics          Broker 主题元数据（需 broker 扩展）
        kgov report          治理报告生成与导出
        kgov export          通用导出
    每个子命令可用 -h 查看详细参数说明。

3.2 schema-diff（Schema 演进兼容性检测）

    功能：比较两个 Avro / JSON Schema，判定兼容级别并输出升级指引。

    命令格式：
        kgov schema-diff --before <schema-a> --after <schema-b>
            [--format avro|json] [--subject <主题>] [--json]
            [-o <输出文件>]

    Schema 来源可为本地文件或 Schema Registry 地址：
        kgov schema-diff --before v1.json --after v2.json
        kgov schema-diff \
            --before http://registry:8081/subjects/payments-value/versions/1 \
            --after  http://registry:8081/subjects/payments-value/versions/2
    也支持简写引用（registry 地址/主题/版本号）：
        kgov schema-diff --before registry:8081/payments-value/1 \
            --after registry:8081/payments-value/2 \
            --subject payments-value --json

    输出：默认输出 Markdown 变更清单（含改动路径、前后类型、变更说明），
    加 --json 或输出文件以 .json 结尾时输出 JSON 兼容性矩阵
    （含 subject、format、kind、compatible、results）。
    退出码：整体兼容性为 Breaking 时返回 1，否则返回 0。

3.3 check（脏数据规则扫描 / CI 门禁）

    功能：按规则 DSL 对消息字段执行约束校验，输出违规样本。

    命令格式：
        kgov check --config <rules.yaml> --messages <messages.json>
            [--max-violations N] [-o violations.json] [--quiet]

    数据源二选一：
        --messages <file>            本地 JSON 消息 fixture；
        --broker host:port --topic T 直接扫描线上消息（需 broker 扩展，
                                     可选加 --schema-registry URL 解码
                                     Confluent Wire Avro）。

    输出：违规明细（规则、主题、分区、偏移量、键、字段、失败检查项、
    消息说明），JSON 或文本。
    退出码：0 = 无违规或违规数在门禁内；1 = 发现违规且超出门禁；
    若同时未指定任何数据源，报运行时错误（退出码 3），避免空扫描
    静默通过 CI。

3.4 registry（Schema Registry 客户端）

    功能：拉取注册表 subject / Schema / 兼容级别，导出离线 fixture。

    命令格式：
        kgov registry --registry-url http://localhost:8081 [-o registry.json]
        kgov registry --registry-url http://localhost:8081 \
            --subject payments-value

    不带 --subject 时输出全量列表：{"subjects": {...}, "generated_at": ...}；
    指定 subject 时输出该主题各版本的 id / version / compatibility /
    schema。

3.5 topics（Broker 主题元数据）

    功能：连接真实 Kafka，拉取主题名称、分区数、副本因子。

    命令格式：
        kgov topics --bootstrap localhost:9092 [-o topics.json]
    需要执行 pip install -e ".[broker]" 并保证集群可达。

3.6 report（治理报告）

    功能：汇总主题清单，计算 owner、标签、Schema 状态、陈旧度、
    违规计数，导出 CSV / JSON。

    命令格式：
        kgov report --topics topics.json
            [--registry registry.json]
            [--groups consumer_groups.json]
            [--rules rules.yaml --messages messages.json
             | --violations violations.json]
            [--format json|csv] [-o report.json|report.csv]

    输出列：name, owner, tags, partitions, replication_factor,
    schema_subject, schema_version, schema_state, latest_message_at,
    last_consumed_at, stale, violation_count。
    陈旧度（stale）：主题有消费组时按最近消费时间是否超过 3 天判定；
    无消费组时按最近消息时间是否超过 2 天判定（阈值均可配置）。

3.7 export（通用导出）

    功能：将指定类型以指定格式导出到文件。

    命令格式：
        kgov export --type report --topics topics.json --format csv \
            -o report.csv
        kgov export --type schema-diff --format markdown \
            --before v1.json --after v2.json -o diff.md
    --type 支持 report / schema-diff，--format 支持 json / csv /
    markdown（与输出文件扩展名联动）。

4 配置与参数
============================================================

4.1 规则文件（rules.yaml / rules.json）
    版本字段 version: 1；topic 为应用主题（缺省 "*" 全主题）；
    rules 或直接以顶层 fields 声明字段约束。支持的约束项如下：

        约束项        取值示例                    说明
        ------------  --------------------------- ------------------
        type          string / integer / number / 字段值类型（int 与
                      boolean / array / object ...  integer 等价，number
                                                   接受整数与浮点）
        required      true                         字段必须存在
        non_null      true                         字段不得为 null
        enum          [ACCEPTED, PENDING]          取值必须属于枚举集合
        pattern       "^pay_[0-9]+$"               取值必须匹配正则
        range         {minimum: 0, maximum: 100}   数值必须落入闭区间

    示例：
        version: 1
        topic: payments
        fields:
          payment_id:
            type: string
            required: true
            pattern: "^pay_"
          amount_cents:
            type: integer
            required: true
            non_null: true
            range: {minimum: 0, maximum: 1000000}
          status:
            type: string
            enum: [ACCEPTED, PENDING, REJECTED]

4.2 消息 fixture（messages.json）
    两种格式皆可：
        {"topic": "payments", "partition": 0,
         "messages": [{"offset": 0, "key": "k1", "value": {...}}, ...]}
    或裸数组 [{"offset": 0, "key": "k1", "value": {...}}, ...]。

4.3 治理报告输入数据
    - topics.json：
        {"topics": [{"name", "partitions", "replication_factor",
          "owner", "tags[]", "schema_subject", "latest_message_at"}]}
    - registry.json（兼容 Confluent wire 形式）：
        {"subjects": {"<subject>": [{"id", "version", "compatibility",
          "schema"}, ...]}}
    - consumer_groups.json：
        {"groups": {"<topic>": {"topic", "group", "last_consumed_at",
          "consumer_count"}}}

4.4 陈旧度阈值
    消费者宽限：consumer_grace_seconds，默认 86400*3（3 天）；
    生产者宽限：producer_grace_seconds，默认 86400*2（2 天）；
    无消费组且无消息记录时置 no_consumer_since_epoch。

4.5 退出码约定（CI 门禁）
        | 码 | 含义                            |
        |----|---------------------------------|
        | 0  | 通过（无违规/兼容/输出成功）    |
        | 1  | 门禁失败（违规、Breaking 差分） |
        | 2  | 用法/配置错误（argparse/校验）  |
        | 3  | 运行时错误（文件缺失/解析失败） |

5 故障处理与常见问题（FAQ）
============================================================

5.1 常见错误提示与处理
    - "kgov: 命令行未找到"：软件未安装或虚拟环境未激活，请执行
      Section 2.2 安装步骤并激活 .venv。
    - "ModuleNotFoundError: No module named 'confluent_kafka'"：
      当前未安装 broker 扩展，执行 pip install -e ".[broker]"；
      check/topics 涉及真实集群的功能需要该扩展。
    - "文件不存在 / 解析失败（文件缺失、解析失败）"：检查 --before/
      --after/--config/--messages/--topics 等参数路径是否正确，
      规则或 Schema 文件是否为合法 JSON / YAML。
    - "必须提供数据源"（check 退出码 3）：check 命令必须带
      --messages 或 --broker --topic 之一，避免空扫描静默通过 CI。
    - "连接注册表失败 / 注册表不可达"：确认 --registry-url 正确、
      网络可达；本地无注册表时可改用 MockRegistry 或文件 fixture。
    - "无法解码消息"：线上消息无法按 JSON 解析时，软件自动尝试
      Confluent Wire Avro 解码（需给定 --schema-registry），再失败则
      回退为文本 / 十六进制，不会中断扫描，可将原始样本导出分析。

5.2 常见问题（FAQ）
    Q1：软件必须联网使用吗？
    A1：不需要。核心功能基于文件 fixture 完全离线运行；仅
       registry / topics / check --broker 在连接在线服务时需要网络。
    Q2：如何把 kgov 接入 CI 流水线？
    A2：在流水线执行 kgov check --config rules.yaml --messages
        sample.json，按退出码（0 通过 / 1 门禁失败）判定即可；可用
        --max-violations 设置允许的违规数量上限。
    Q3：Schema 兼容性是如何判定的？
    A3：逐字段、逐类型比较，新增可选字段为 Additive，删除字段 / 收紧
        类型 / 提升必填为 Breaking，放宽类型为 Non-Breaking；只要有
        Breaking 项整体即判 Breaking。
    Q4：陈旧度阈值如何调整？
    A4：在代码中调整 StalenessSettings 的 consumer_grace_seconds（默认
        3 天）与 producer_grace_seconds（默认 2 天）参数。
    Q5：能不能核对源程序信息？
    A5：可以。源程序量由 kgov 包源码统计，口径为：剔除 # 注释
        行与空行后统计代码行数。主程序（kgov 包，不含 tests）约
        2708 行，分模块为：init 6、model 154、rules_errors 7、
        registry 130、report 258、mock_registry 263、broker 362、
        rules 409、cli 536、schema_diff 583。连同 tests 测试代码
        （约 5152 行）一并统计约 7860 行。若把空行与注释也计入，
        主程序物理行数约 3634 行，含 tests 总计约 10320 行。
        读数可用 wc -l 与去空白/注释脚本按上述口径复核。
